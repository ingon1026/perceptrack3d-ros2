## 1. 상태와 모델

상태 벡터 x (6,) 와 등속(constant velocity, CV) 모델:

```
x = [px, py, pz, vx, vy, vz]ᵀ          (m, m/s)

x_k = F x_{k-1} + w,   w ~ N(0, Q)
z_k = H x_k     + v,   v ~ N(0, R)      z = 융합이 준 3D 중심 (3,)

F = [ I3   dt·I3 ]        H = [ I3  0 ]        (위치만 관측, 속도는 간접 추정)
    [ 0    I3    ]
```

- **dt = 0.1 s** (KITTI 10 Hz). `step()` 을 프레임 순서대로 매번 호출한다고 가정한다.
- **Q (프로세스 잡음)** — "등속 가정이 틀리는 정도". 단순 대각 모델을 택했다:
  `Q = diag(σp², σp², σp², σv², σv², σv²)`, σp = `process_noise_pos`, σv = `process_noise_vel`.
  물리적으로 더 정확한 대안은 이산 백색 가속(DWNA) 모델 `Q = σa² [[dt⁴/4, dt³/2],[dt³/2, dt²]]` (축마다) 인데,
  파라미터 하나(σa)로 위치·속도 잡음이 자동으로 묶인다. 기준선은 읽기 쉬운 대각형을 쓰고, 개선 단계에서 비교해 볼 수 있다.
- **R (관측 잡음)** = `measurement_noise²·I3`. 융합이 내놓는 중심의 오차. LiDAR 는 보이는 면(앞면/옆면)만 찍히므로
  중심 추정은 물체 크기의 절반 정도(~1 m) 까지 흔들릴 수 있다. 실제 데이터에서는 이 값을 키워야 할 가능성이 크다.
- **P0 (초기 공분산)** = diag(R, `initial_vel_std²`·I3). 첫 관측에서 속도는 전혀 모르므로 크게 잡는다.
  자차 기준 상대속도는 마주 오는 차의 경우 25 m/s 를 넘으므로 10 m/s 로 두었다.

## 2. 칼만 필터 한 사이클

```
예측   x⁻ = F x                 P⁻ = F P Fᵀ + Q         (불확실성이 커진다)
갱신   y  = z − H x⁻            혁신(innovation): 예측과 관측의 차이
       S  = H P⁻ Hᵀ + R         혁신 공분산 (3×3)  ← 게이팅에도 같은 S 를 쓴다
       K  = P⁻ Hᵀ S⁻¹           칼만 이득 (6×3): "관측을 얼마나 믿을지"
       x  = x⁻ + K y
       P  = (I − K H) P⁻         (불확실성이 줄어든다)
```

직관: `K ≈ P⁻ / (P⁻ + R)`. 예측이 불확실(P⁻ 큼) 하면 K → 1 (관측을 따름), 관측이 불확실(R 큼) 하면 K → 0 (예측을 따름).
K 의 아래 3행(속도 행)이 0 이 아닌 이유는 P⁻ 에서 위치–속도 상관(F P Fᵀ 의 dt 항) 이 생기기 때문이다.
그래서 위치만 관측해도 속도가 추정된다.

코드에서는 `KalmanFilterCV.predict/update` 가 위 식을 그대로 옮긴 순수 함수다 (`np.linalg.inv(S)` 는 3×3 이라 그대로 씀).

## 3. 마할라노비스 게이트

```
d² = (z − H x⁻)ᵀ S⁻¹ (z − H x⁻)
```

- 유클리드 거리를 "예측 불확실성 S 로 정규화" 한 것. S 가 크면(오래 못 본 트랙) 같은 거리라도 d² 가 작다 → 게이트가 자동으로 넓어진다.
- 모델이 맞다면 d² 는 **자유도 3 인 chi² 분포** 를 따른다 (관측 차원 = 3). 따라서 게이트 임계값은 chi² 분위수로 정한다:
  p = 0.95 → 7.81, p = 0.975 → 9.35, p = 0.99 → 11.34. 설정값 9.21 은 대략 p ≈ 0.973 에 해당한다.
- 의미: "진짜 매칭이 게이트 밖으로 밀려날 확률 ≈ 2.7 %". 게이트를 키우면 놓침은 줄지만 오검출을 흡수할 위험이 커진다.
- 알려진 약점: S 가 큰(불확실한) 트랙이 관측을 "훔치기" 쉽다. 개선안은 비용에 `ln det S` 를 더하는 것(우도 기반) 이다.
- `gating: euclidean` 은 단순 거리(m) 게이트. 디버깅·비교용.

## 4. 헝가리안 할당 (Hungarian / linear_sum_assignment)

- 비용 행렬 C (T × D): 트랙 i 와 관측 j 의 d² (또는 거리). 게이트 밖·클래스 불일치는 `np.inf`.
- 목적: 총비용 Σ C[i, a(i)] 가 최소가 되는 **일대일** 할당. 탐욕(greedy) 은 가까운 것부터 먹어치워 교차 상황에서 틀리기 쉽다.
- scipy 는 inf 를 못 다루므로 큰 유한값(어떤 유한 비용의 합보다 큰 값) 으로 바꿔 풀고, 결과 중 원래 inf 였던 쌍을 버린다.
  큰 값이 유한 비용 합보다 크면 솔버는 inf 쌍을 "어쩔 수 없을 때만" 고르므로, 버려도 나머지 매칭은 최적이다.
- 반환: `matches [(track_idx, obj_idx)]`, `unmatched_tracks`, `unmatched_objects`.

## 5. 트랙 생명주기

```
                 미매칭 관측
                     │
                     ▼
              ┌──────────────┐  hits >= min_hits   ┌──────────────┐
              │  tentative   │ ──────────────────▶ │  confirmed   │ ──▶ step() 반환
              │ hits=1,      │                     │ (유지됨)      │
              │ misses=0     │                     └──────┬───────┘
              └──────┬───────┘                            │
                     │  매칭: hits+1, misses=0, history 추가│
                     │  미매칭: misses+1 (예측값 유지 = coasting)
                     ▼                                    ▼
              misses > max_misses ───────────────▶  삭제 (id 재사용 없음)
```

- `track_id` 는 1 부터 단조 증가. tentative 로 끝난 트랙도 id 를 소비하므로 "생성된 id 수 ≠ 확정 트랙 수".
- 반환 목록에는 coasting 중인 confirmed 트랙도 포함된다 (`misses > 0`). 관측된 것만 원하면 `misses == 0` 으로 거른다.
- `history` 는 관측으로 갱신된 프레임의 (frame_id, x, y, z) 만 쌓는다. coasting 위치는 `state` 에서 읽는다.
- `age` 는 생성 후 지난 프레임 수 (`predict` 마다 +1).

## 6. 파라미터 튜닝 가이드 (`configs/kitti.yaml` → `tracking`)

| 키 | 커지면 | 작아지면 |
|---|---|---|
| `measurement_noise` | 관측을 덜 믿음 → 궤적이 매끄럽지만 반응이 느림, 게이트도 넓어짐 | 관측을 그대로 따라감(지터), 게이트 좁아져 놓침 증가 |
| `process_noise_pos/vel` | 급가속·회전에 잘 따라감, 평활 효과 감소 | 부드럽지만 기동 시 예측 이탈 → 게이트 밖으로 나가 ID 끊김 |
| `initial_vel_std` | 첫 두 프레임의 게이트가 넓어 빠른 물체도 붙음, 대신 근처 오검출 흡수 | 빠른(마주 오는) 차가 2 번째 프레임에서 새 트랙으로 갈라짐 |
| `gate_mahalanobis` | 놓침 감소, 오검출·이웃 물체 흡수 증가 | 반대. chi² 표로 p 값과 함께 정하기 |
| `min_hits` | 유령 트랙 억제, 확정까지 지연 (min_hits−1 프레임) | 빨리 확정, 단발 오검출도 트랙이 됨 |
| `max_misses` | 가림(occlusion) 을 오래 견딤, 대신 죽은 물체의 유령이 오래 남고 드리프트 | ID 자주 끊김 |
| `match_same_class` | (true) 다른 클래스끼리 안 섞임. YOLO 가 car↔truck 을 깜빡이면 ID 끊김 | (false) 클래스 무시. 사람+자전거 이중 검출은 별도 트랙으로 남음 |

순서 제안: (1) `measurement_noise` 를 융합 오차(Phase 8 의 중심 오차 통계) 에 맞춤 → (2) 게이트를 chi² 로 고정 →
(3) `process_noise` 로 기동 추종 vs 평활 균형 → (4) `min_hits`/`max_misses` 로 유령·끊김 트레이드오프.

## 7. 실패 모드

- **ID 스위치**: 두 물체가 게이트 안에서 교차하면 비용이 비슷해져 뒤바뀔 수 있다. 위치만 쓰는 비용의 한계 —
  속도 방향·크기·외형(appearance) 을 비용에 넣으면 줄어든다.
- **유령 트랙**: 오검출이 `min_hits` 프레임 연속되면 확정된다. 배경 구조물(가드레일·간판) 에 YOLO 가 반복 오검출하는 경우가 전형적.
- **coasting 드리프트**: 놓친 동안 예측만 하므로 속도 추정이 틀리면 매 프레임 dt·v 만큼 멀어져 재검출을 게이트 밖으로 놓친다.
  `max_misses` 를 키울수록 심해진다.
- **자차 회전**: Velodyne 프레임은 자차와 함께 돈다. 정지 물체도 자차가 회전하면 프레임 안에서 호를 그리며 움직여 등속 모델이 깨진다.
  OXTS(IMU/GPS) 로 자차 운동을 보상하면 개선된다 (Phase 7 범위 밖).
- **크기·클래스**: 필터는 위치만 추정한다. `size` 는 마지막 관측값을 저장할 뿐 평활하지 않는다.
